# Coding Standard (统一跨语言代码规范与工程基线)

这是一个独立、可复用、跨语言（C、Rust、Python 等）的代码规范与自动化配置仓库。

## 1. 核心设计原则

1. **通用原则统一，语言规范细分**: 通用工程原则（命名、复杂度、防御性编程、资源所有权）全语言一致；语法与范式按语言特化。
2. **复用成熟工具**: 基于行业标准工具（`clang-format`、`rustfmt`、`clippy`、`ruff`），不重复造轮子。
3. **单源维护与版本化**: 规范源文件在本仓库单源维护，接入项目通过 `.coding-standard.toml` 锁定版本与文件哈希。
4. **分层覆盖与无冲突更新**: 核心配置托管在 `.base` 文件中，项目特异性定制保留在 `.override` 文件中，上游版本升级时自动合并重编，彻底避免“定制导致无法升级”的死局。
5. **安全与零第三方依赖**: 全套管理脚本（`install.py`, `sync.py`, `check.py`）采用纯 Python 3.10+ 标准库实现，防范路径越界，严禁静默覆盖用户修改。

## 2. 仓库结构

```text
coding-standard/
├── README.md                          # 本文档
├── VERSION                            # 当前规范发布版本 (例如 0.1.0)
├── CHANGELOG.md                       # 版本演进记录
├── .gitignore                         # 仓库忽略规则
│
├── docs/                              # 规范文档中心
│   ├── principles.md                  # 跨语言通用工程原则 (MUST / SHOULD / MAY)
│   ├── code-review.md                 # 代码评审指引与检查清单
│   └── languages/                     # 语言专属详细规范
│       ├── c.md                       # C 语言规范 (含嵌入式/RTOS/裸机附则)
│       ├── rust.md                    # Rust 规范 (2021 Edition / API Guidelines)
│       └── python.md                  # Python 规范 (3.10+ / 现代 PEP 8)
│
├── profiles/                          # 语言专属配置模版源文件
│   ├── common/                        # 通用配置 (.editorconfig)
│   ├── c/                             # C 语言配置 (.clang-format.base)
│   ├── rust/                          # Rust 配置 (rustfmt.base.toml)
│   └── python/                        # Python 配置 (ruff.base.toml, ruff.toml)
│
├── templates/                         # 模板与外部集成示例
│   ├── git-hooks/                     # Git pre-commit 钩子示例
│   └── ci/                            # GitHub Actions 与 GitLab CI 流水线模板
│
├── scripts/                           # 纯标准库自动化管理脚本
│   ├── install.py                     # 初始化接入与配置安装
│   ├── sync.py                        # 安全同步与配置更新
│   ├── check.py                       # CI 配置完整性与版本校验
│   └── lib/                           # 核心逻辑库 (manifest, compiler, profiles)
│
└── tests/                             # 自动化单元测试 (覆盖率与边界测试)
```

## 3. 快速上手

管理脚本位于 `scripts/` 目录下，可以在任意工作目录直接执行。

### 3.1 为新项目或已有项目安装规范 (`install.py`)

#### C / 嵌入式 C 项目
```bash
python3 /path/to/coding-standard/scripts/install.py \
    --profile c \
    --target ../my_c_project
```
> 注：支持使用 `--profile embedded-c` 作为别名，效果相同。

#### Rust 项目
```bash
python3 /path/to/coding-standard/scripts/install.py \
    --profile rust \
    --target ../my_rust_project
```

#### Python 项目
```bash
python3 /path/to/coding-standard/scripts/install.py \
    --profile python \
    --target ../my_python_project
```

#### 混合语言项目 (例如 C + Python)
```bash
python3 /path/to/coding-standard/scripts/install.py \
    --profile c,python \
    --target ../my_hybrid_project
```

安装完成后，目标工程根目录将生成 `.coding-standard.toml` 清单文件，例如：
```toml
# Generated by coding-standard. DO NOT EDIT MANUALLY.
version = "0.1.0"
repository = "coding-standard"
updated_at = "2026-10-16T14:35:00Z"
profiles = ["common", "c"]

[[files]]
path = ".editorconfig"
profile = "common"
sha256 = "17e57c6b..."
is_base = false

[[files]]
path = ".clang-format.base"
profile = "c"
sha256 = "ec6a8bfb..."
is_base = true
```

---

### 3.2 检查项目规范状态 (`check.py`)

在本地自检或 CI 流水线中验证项目是否合规接入了规范：

```bash
python3 /path/to/coding-standard/scripts/check.py --target ../my_project
```

- 若所有受管理配置文件完好无损且 SHA 匹配，返回状态码 `0`。
- 若缺少受控文件、清单损坏或受管基础文件被违规篡改，输出明确的失败原因与修复建议，并返回非零状态码 `1`。

---

### 3.3 更新规范版本与同步配置 (`sync.py`)

当规范仓库发布新版本（通过 Git 拉取了新 commit 或切换到新 tag）后，同步更新下游项目：

```bash
python3 /path/to/coding-standard/scripts/sync.py --target ../my_project
```

`sync.py` 会读取项目清单中启用的 profile，更新 `.base` 配置文件，并重新编译生成最终配置文件。

## 4. 个性化微调与冲突解决策略

### 4.1 项目私有规则定制 (推荐)

为保证项目既能享受集中规范的统一演进，又能满足自身特殊需求，本框架提供**分层覆盖机制**：

- **C 语言**: 在项目根目录下创建 `.clang-format.override`，写入需要覆盖的键值对。
  ```yaml
  ColumnLimit: 120
  IndentWidth: 4
  ```
  运行 `sync.py` 时，工具会自动将 `.clang-format.base` 与 `.clang-format.override` 合并编译为 `.clang-format`。
- **Rust 语言**: 在项目根目录下创建 `rustfmt.override.toml`。
  ```toml
  max_width = 120
  ```
  `sync.py` 会将基准配置与 override 合并生成 `rustfmt.toml`。
- **Python 语言**: 项目根目录下的 `ruff.toml` 包含 `extend = "ruff.base.toml"`，可以直接在 `ruff.toml` 中追加或覆盖规则。

### 4.2 处理直接修改造成的同步冲突

如果项目成员直接修改了受管文件（例如 `.clang-format.base`），`sync.py` 会通过 SHA-256 校验和识别到冲突并发出告警，**默认绝不静默覆盖**：

```text
[WARNING] Conflicts detected (preserved without overwriting):
  ! .clang-format.base (locally modified, checksum mismatch with manifest; use --force to overwrite)
```

**解决方案**:
1. **推荐**: 将本地修改转移至对应的 `.override` 文件中，然后重新运行 `sync.py`。
2. **强制覆盖**: 若确认放弃本地直接修改，传入 `--force` 参数：
   ```bash
   python3 /path/to/coding-standard/scripts/sync.py --target ../my_project --force
   ```

## 5. CI / CD 与 Git Hooks 集成

### 5.1 Git Pre-commit 钩子

在目标项目中接入自动校验：
```bash
cp templates/git-hooks/pre-commit ../my_project/.git/hooks/pre-commit
chmod +x ../my_project/.git/hooks/pre-commit
```

### 5.2 GitHub Actions 集成

在项目的 `.github/workflows/ci.yml` 中添加检查步骤：
```yaml
- name: Verify Coding Standard
  run: |
    git clone --depth 1 https://gitee.com/wangxuran/coding-standard.git /tmp/coding-standard
    python3 /tmp/coding-standard/scripts/check.py --target .
```

## 6. 如何扩展新增一种语言或 Profile

以新增 `go` 语言为例：

1. **添加规范文档**: 创建 `docs/languages/go.md`，制定 Go 语言的代码与错误处理规范。
2. **添加配置源文件**:
   - 创建 `profiles/go/.golangci.yml.base`
3. **在 `scripts/lib/profiles.py` 中注册**:
   ```python
   AVAILABLE_PROFILES = ["common", "c", "rust", "python", "go"]

   PROFILE_SPECS["go"] = [
       ProfileFileSpec(
           src_rel_path=".golangci.yml.base",
           target_rel_path=".golangci.yml.base",
           is_base=True,
           compiled_filename=".golangci.yml",
           override_filename=".golangci.override.yml",
       )
   ]
   ```
4. **添加对应单元测试**: 在 `tests/` 中扩充测试用例并执行 `python3 -m unittest discover tests`。
